### F4 plan: bigger maps (needs the user's go-ahead)

1. **Protocol 38:** positions are `cell u16 + offX u8 + offZ u8` today, so 65,536 cells (256 × 256) at most. Widen the cell to 3 bytes (u24) everywhere a position goes on the wire, with golden bytes, B's decoders and the replay format.
2. **Sim grids:** sensor maps, flow fields and the contact grid sized from the map; measure `profile_match` and the soak on a 512 × 512 map (4,096 studs, 262,144 cells) with 16 players.
3. **Maps:** a 512 × 512 medium map first; 1,024 × 1,024 (8,192 studs, 1 M cells) only if the 512 numbers leave room (flow-field memory and Studio terrain size are the risks).
4. **D:** the map picker by size (small 256, medium 512, large 1,024).

#### Measured (2026-10-26, Lune on the dev PC, a throwaway probe)

600 units (two mixed armies, as `lune run stress`), 450 ticks (30 s), generated maps, map limit raised for the probe only. Bytes are player 1's, in today's format (cells past 65,535 written modulo, so the counts are exact); "widened" is what the format below adds.

| Map | Build | Heap peak | Tick avg / p95 / max (budget 66.7) | Pathing avg | KB/s per player (budget 35) | Widened | Join burst (SIGHT_ROWS) |
|---|---|---|---|---|---|---|---|
| 256 (2,048 studs) | 0.6 s | 40 MB | 8.4 / 14.3 / 28 ms | 0.3 ms | 12.2 | +0.1 | 2 KB |
| 512 (4,096 studs) | 0.8 s | 106 MB | 8.7 / 15.6 / 22 ms | 1.4 ms | 11.4–12.0 | +0.2 | 8 KB |
| 1,024 (8,192 studs) | 3.5 s | 350 MB | 12.8 / 22.8 / 49 ms | 3.5 ms | 12.0–13.6 | +0.2 | 33 KB |

- **The network load doesn't grow with the map.** Tactical follows the camera and strategic the units, so bytes per player stay ~12 KB/s at every size. Only the one-off join burst grows (the whole sight map once): 33 KB at 1,024 is about a second of the budget, inside the loading screen.
- **The sim cost does.** 512 costs what 256 costs. 1,024 is +50% tick, 3.5 s to build and 3–4× the heap; it fits the budget, but leaves less room for 16 players.

#### Decision: the network load is fine; 512 first, 1,024 after a Studio check

Format (protocol 38) with no extra bytes on the hot records:
- **Positions** (tactical, ENTER, WRECK, commands): `x u16, z u16` in quarter studs, from the map's corner minus a margin. Same 4 bytes as today, 16,384 studs of range: a 1,024 map plus 4,096 studs past each edge. Precision 0.25 stud instead of 0.03 (invisible once interpolated).
- **Strategic:** x and z in 11 bits each at 8 studs (today's precision), in the 16 cell bits plus the 7 reserved ones: still 7 bytes.
- **SIGHT_CELLS** u16 → u24 per cell (+0.2 KB/s), **SIGHT_ROWS** firstRow u16, **CAMERA** cells u16, ALERT position like the others.
- **Aircraft past the edge (F3):** the margin carries them, so the sim's map clamp can relax to "map + 512 studs" in the same change.
- 1,024 maps: after a Studio check of server memory and the client's terrain and memory at 8,192 studs.
