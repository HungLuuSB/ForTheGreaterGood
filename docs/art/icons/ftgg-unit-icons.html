Unit icon set

Style B, "Line": a crisp white frame over smoked glass, a white symbol with a hairline dark edge, and a soft shadow, so icons sit on the terrain like display markings. The grammar is unchanged: the frame is the unit type, the square pips under it are the tech level (none for T1, two for T2, three for T3), and the symbol is the weapon or role. The two Commanders are the exception: each icon is its own model's head. Every icon is one white image with dark edges, tinted per team in Roblox through ImageColor3. This set (draft 7, approved 29 Oct 2026) maps every one of the game's 203 unit definitions exactly once (read 29 Oct 2026, main 7ac4df3f), plus one placeholder per frame for units that don't have an icon yet. Retired units keep an icon for old replays.

Placeholder rule

For the atlas builder and the client

A unit def that is in no list on this sheet gets the placeholder of its type instead of a blank radar contact. The placeholder is picked from the def, in this order:

  1. Structure (domain "structure"): placeholder_defense_t0 if it has a weapon, otherwise placeholder_structure_t0.
  2. Air: move class HELI → placeholder_helicopter_t0, otherwise placeholder_aircraft_t0.
  3. Naval: move class SUB → placeholder_submarine_t0, otherwise placeholder_ship_t0.
  4. Ground: move class WALKER or AMPHIB_WALKER → placeholder_walker_t0; AMPHIB → placeholder_amphibious_t0; HOVER → placeholder_hover_t0; otherwise placeholder_vehicle_t0.

Placeholders carry ph: 1, an empty defs and no tier pips. Their tile keys follow the sheet's rule, slug(name)_t<tier>. The build tool should list every def that fell back to a placeholder as a warning, so missing icons stay visible without breaking the build. The same rule picks every mapped unit's frame, with two kinds of exception. A structure may take the structure or the defense frame by role: the shield domes are defenses, the nuke silos are structures. A Commander draws its head (sil), but its frame stays walker, so its radar contact is a plain walker.
